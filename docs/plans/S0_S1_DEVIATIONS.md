# S0/S1 偏差决策记录

按 `docs/plans/S0_S1_PLAN_v3.md` 偏差协议维护。每条含：偏差、原因、备选方案对比、结论与理由。

## DEV-1（S1-W3）：相对路径 cwd 输入抛 `INVALID_REQUEST`

- **偏差内容**：设计文档 §6.2 只规定「解析绝对路径」并给出平台大小写策略，未定义非绝对路径输入的行为；计划 v3 W3 验收补充为「相对路径输入抛 INVALID_REQUEST」，实现照此落地（`normalizeWorkspaceCwd`）。
- **原因**：`agent.session.header.cwd` 的 Host 契约是绝对路径（§6.2 前提）；相对输入只可能来自调用方缺陷，静默哈希会产生不可追溯的伪 scope key，违背隔离模型意图。
- **备选方案对比**：
  1. 相对路径按 process.cwd() 拼接后继续 —— 引入进程环境依赖，破坏纯函数性质，且拼接结果因启动目录不同而不稳定；
  2. 静默原样哈希 —— 同一 workspace 可能产生多个 key，且无任何告警；
  3. 显式抛 `INVALID_REQUEST`（采纳）—— 失败显式化，符合第 2 节「来源无法解析时明确失败」的同构原则。
- **结论**：采纳方案 3。理由：故障面最小、可测试、不引入隐藏环境耦合；属于对未定义行为的防御性补充，不改变任何已定义行为。

## DEV-2（S1-W7a）：listMindmaps 增加索引/缓存缺失对账

- **偏差内容**：原实现在 summaries.json 非空时直接短路返回缓存；W7a 测试暴露「记录在 index.json 中存在但缓存无条目时永久不可见」。实施改为：先读 index，若存在缓存未覆盖的 id 则触发全量重建（复用既有批量读取+写回路径），否则维持快速路径。
- **原因**：summaries 是派生缓存而非事实源；index.json 才是权威清单。旧实现把缓存当事实源，会让 legacy fixture、中断写入后的记录静默消失，违背 Phase 1 验收门「旧 fixture 读取通过」。
- **备选方案对比**：
  1. 修改测试为给 fixture 手工补 summary 条目 —— 掩盖缺陷，真实升级场景（缓存与 index 不同步）仍会丢数据；
  2. 每次列表全量重读所有 record 文件 —— 正确但放弃缓存意义；
  3. 缺失对账＋命中走缓存（采纳）—— 快路径成本不变（多一次 readIndex 小文件读取），慢路径仅在检测到缺口时触发。
- **结论**：采纳方案 3。理由：保持 R7 锁定行为不变（损坏 JSON 仍然显式抛错），修复可见性缺陷的最小改动。
